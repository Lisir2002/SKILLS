# 配色与无障碍规范（中文）

> visualization 技能生成图表（Mermaid / SVG / 报告图表）时的**配色与无障碍**依据。
> 目标：色盲友好、对比度达标、形状与颜色双重编码，让每个读者（含色盲与屏幕阅读器用户）都能正确读取图表。

---

## 1. 三条硬规则

1. **不止用颜色编码**（WCAG 1.4.1 Use of Color）：任何信息都必须同时通过**形状 / 标签 / 图案 / 数值**传达。例如折线多系列时，除颜色外还要用线型（实线/虚线/点线）区分。
2. **文字对比度 ≥ 4.5:1**（WCAG 1.4.3 AA）：正文、轴刻度、图例文字相对背景均须达标；大字号（≥18pt 或 14pt 粗体）可放宽到 3:1。
3. **系列 ≤ 7 个**：人类可稳定分辨的颜色上限约 7 种；超过时改用分组、子图或表格。

---

## 2. 内置色板（svg_chart.py）

svg_chart.py 提供三套科学验证的色板，默认 **Okabe-Ito**（唯一经严格色盲模拟验证的默认方案）：

| 色板 | 色值（按顺序） | 适用 |
|------|----------------|------|
| `okabe`（默认） | `#E69F00` `#56B4E9` `#009E73` `#F0E442` `#0072B2` `#D55E00` `#CC79A7` `#999999` | 通用、色盲安全，首选 |
| `tableau` | `#4E79A7` `#F28E2B` `#E15759` `#76B7B2` `#59A14F` `#EDC948` `#B07AA1` `#FF9DA7` `#9C755F` `#BAB0AC` | 商务汇报，专业感强 |
| `antv` | `#5B8FF9` `#5AD8A6` `#5D7092` `#F6BD16` `#E8684A` `#6DC8EC` `#9270CA` `#FF9D4D` `#269A99` `#FF99C3` | AntV 风格，数据产品 |

命令行示例：

```bash
# 默认 Okabe-Ito（推荐）
python3 svg_chart.py --type bar --data '<...>' -o chart.svg
# 商务风格 + 自定色板
python3 svg_chart.py --type line --data '<...>' --palette tableau -o chart.svg
python3 svg_chart.py --type pie --data '<...>' --colors '#4E79A7,#F28E2B,#E15759' -o chart.svg
```

> 自定色板请自行保证：相邻系列可区分（含色盲模拟）、与背景对比达标。

## 3. 对比度速查

对比度 = `(较亮亮度+0.05) / (较暗亮度+0.05)`，其中亮度按 sRGB 线性化加权。常用达标组合：

| 前景 | 背景 | 对比度 | 说明 |
|------|------|--------|------|
| `#333`（深灰文字） | `#fff` | ~12.6:1 | 正文默认，达标 |
| `#666`（次要文字） | `#fff` | ~5.7:1 | 轴刻度/图注，达标 |
| `#888` | `#fff` | ~3.7:1 | 仅可作装饰性网格，不作正文 |
| `#fff` 文字 | `#0072B2`（Okabe 蓝） | ~5.0:1 | 饼图扇形内标签，达标 |
| `#fff` 文字 | `#009E73`（Okabe 绿） | ~2.7:1 | ❌ 不达标，改用深色文字或外置标签 |

判断方法（无需工具，手动估）：白色背景上的正文用 `#333`~`#444` 稳妥；深色填充上的白字需验证填充足够深。

## 4. 双重编码（形状 + 颜色）

除颜色外叠加的第二编码方式：

- **折线多系列**：实线 / 虚线 / 点线（`stroke-dasharray`）+ 不同数据点形状（圆/方/三角）；
- **柱状多系列**：并排分组 + 数值标签 + 图例；
- **饼/环形**：每块外置图例并注明百分比（svg_chart 已内置「标签 + 百分比」双重编码）；
- **散点分类**：不同形状 + 图例。

示例：线型 + 颜色双编码

```svg
<path d="..." fill="none" stroke="#0072B2" stroke-width="2.5"/>            <!-- 销量：实线 -->
<path d="..." fill="none" stroke="#D55E00" stroke-width="2.5" stroke-dasharray="6 4"/> <!-- 成本：虚线 -->
```

## 5. 语义色惯例

非系列分类时，用语义色保持一致：

| 语义 | 推荐色 | 用途 |
|------|--------|------|
| 正向 / 增长 | `#009E73`（绿） | 上升、达标 |
| 负向 / 下降 | `#D55E00`（橙红） | 下降、预警 |
| 中性 / 信息 | `#0072B2`（蓝） | 常规数据、链接 |
| 警示 | `#E69F00`（橙） | 注意、临界 |

注意：Okabe-Ito 的 `#D55E00`（橙红）与 `#E69F00`（橙）在红绿色盲下仍可区分，优于普通「红/绿」。

---

## 6. 无障碍结构（SVG / HTML）

- 每个 `<svg>` 必须有 `<title>` 与 `<desc>`（屏幕阅读器读取图意），并建议 `role="img"` + `aria-labelledby`；
- `<desc>` 写**图意结论**而非罗列数据：如「Q4 为全年最高，达 340」优于「Q1 120，Q2 210…」；
- 图表若嵌入 HTML 报告，正文需有文字版的结论句，不能只放图；
- 打印友好：颜色对比在低质量打印下仍需可辨，深色为主、浅色为辅。

---

## 7. 产出前自检

- [ ] 信息不依赖颜色也能读懂（有形状/标签/数值）
- [ ] 正文与背景对比 ≥ 4.5:1（深灰文字 + 白底稳妥）
- [ ] 系列 ≤ 7 个
- [ ] 每张 SVG 有 `<title>` + `<desc>`，`desc` 含图意结论
- [ ] 正负语义色一致（绿=增长，橙红=下降）
- [ ] 选用了 Okabe-Ito 默认色板（除非有明确理由）
