# 图表选型决策树与设计原则（Chart Guide）

> visualization 技能在"选型"阶段的核心依据。先选对图，再画好图。

---

## 1. 主类型判定（diagram / chart / table / report）

| 你的问题 | 主类型 | 说明 |
|---------|--------|------|
| "这个东西是怎么流转的？" | diagram | 流程 / 关系 / 结构 |
| "数据在不同时间怎么变？" | chart | 有数值、要看趋势/对比/占比/分布 |
| "这些数据逐条对照一下？" | table | 数据罗列、明细、清单 |
| "给领导出一份总结？" | report | 多图 + 表格 + 结论组合 |

> 拿不准就跑：`python3 scripts/viz_advisor.py "<需求描述>"`。

---

## 2. chart 子类型决策树

按**你要回答的问题**选图，不要按"哪种好看"选：

```
数据是数值型，想回答：
├─ 时间上怎么变化？          → 折线 line（1 条趋势） / 面积 area（强调累积量）
├─ 哪一类更大/更小？         → 柱状 bar（分类少） / 横向条形（分类多或名称长）
├─ 占比构成，各部分占整体多少？→ 饼图 pie（≤6 类，且只看占比不看精确差）
├─ 两个变量的关系？          → 散点 scatter
├─ 数值分布在哪？            → 直方图 histogram
├─ 多个维度同时对比？        → 分组柱状 / 堆叠柱状
├─ 排名？                   → 横向条形（从大到小排序）
└─ 地图/热力？              → 热力图 heatmap（区域数据）
```

**决策原则**：
1. **一张图只回答一个问题**；问题多于一个就拆图；
2. **饼图慎用**：人类对角度感知不准，占比差异 <5% 时饼图会误导——改用条形或直接给数值；
3. **类别多（>7）时不用饼图 / 柱状堆太挤**：先聚合"其他"，或改表格；
4. **趋势永远用折线**，不要用柱状假装趋势；比较大小用柱状，不要用折线。

---

## 3. 设计原则（Tufte 精华）

1. **数据墨水比**：画面里每一滴墨水都要承载信息。删掉装饰性背景、3D 效果、不必要的网格线、无意义渐变；
2. **无装饰性 3D / 阴影 / 立体**：图表是信息载体，不是宣传海报；
3. **坐标轴诚实**：
   - 不截断坐标轴来夸大差异（要截断必须标注"起点非 0"）；
   - 数值轴标注**单位**与**刻度**；
4. **颜色有语义**：颜色 ≤7 种；同色系 = 同类数据，不同色 = 不同类；红/绿等语义色全局一致（红=警告/下降、绿=正常/上升），不滥用；
5. **标注结论**：峰值、拐点、异常点、目标线要有标注，否则读者不知道看哪；
6. **标题即结论**：图的标题写结论而非描述（"Q2 营收环比 +18%，创历史新高" 优于 "营收柱状图"）；
7. **图注**：图表下方给一句话"该怎么读这张图"。

---

## 4. 常见误区（对照自检）

| 误区 | 问题 | 正确做法 |
|------|------|---------|
| 用饼图看趋势 | 饼图没有时间维 | 折线 |
| 用柱状做占比 | 柱状强调大小对比，不强调整体 | 饼图（≤6类）或条形 |
| 截断 Y 轴 | 夸大差异 | 从 0 开始，或显式标注截断 |
| 颜色太多 | 无法分辨语义 | ≤7 种，语义统一 |
| 双坐标轴乱标 | 误导相关性 | 确需双轴时标注清楚左右轴含义 |
| 每张图没结论 | 读者自行解读 | 配一句"结论" |

---

## 5. 输出前自检清单

- [ ] 主类型正确（diagram/chart/table/report）
- [ ] 子类型回答的问题是用户想知道的
- [ ] 数据无伪造、坐标未夸大、单位有标注
- [ ] 颜色 ≤7 种且语义一致
- [ ] 有标题 + 图注（结论一句）
- [ ] 可维护：大数据不硬编码，用脚本生成
