# 域外移植 · 领域规则库

> frame-breaker Step 3 使用：从**无关领域**借一个"规则系统/世界观"来**重定义本题**
> ——不是借点子，是借表征框架（换个坐标系，而不是换个说法）。
> 用法：先看你的问题属于哪类，再从"很远"的领域借规则；借来后把本题的术语
> 全部翻译成该领域术语，重新描述一遍问题，观察搜索空间发生了什么变化。

## 一、规则库（20+ 领域世界观）

### 人文艺术类

| 领域 | 规则系统/世界观 | 可参考用法 |
|------|------------------|------------|
| 戏剧 | 悬念-期待管理：等待被设计成体验的一部分 | 电梯等待→幕间 |
| 音乐 | 和声解决：先制造不和谐，解决时才动人 | 先制造"不适"再给方案 |
| 宗教仪式 | 仪式感：重复动作承载意义 | 把无意义操作变仪式 |
| 侦探推理 | 不在场证明：怀疑"理所当然在场"的一方 | 质疑默认在场的参与者 |
| 语言学 | 词义随使用演化：旧词装新义 | 给旧概念重新命名以解锁联想 |
| 考古学 | 断代：从碎片重推完整系统 | 从碎片推断原框架 |
| 体育战术 | 攻防转换：防守即进攻的起点 | 把"补短板"改"用短板" |

### 社会/系统类

| 领域 | 规则系统/世界观 | 可参考用法 |
|------|------------------|------------|
| 蜂群 | 分布式决策：无中心，个体规则涌现整体行为 | 去掉中心调度 |

| 科幻设定 | 时间循环/平行宇宙：改变因果结构 | 不改变事件，改变时间结构 |

## 二、移植四步法

1. **选域**：从上面选一个与本题"最无关"的领域（距离越远，重定义越可能真变）；
2. **翻译**：把本题所有术语逐词翻译成该领域术语，重新描述一遍问题；
3. **观察**：翻译后的问题出现了哪些原问题没有的"新变量/新约束/新评价"？
4. **回流**：把新问题里冒出来的东西翻译回原领域语言——这就是新框架的雏形。

## 三、移植示例

**题目**：给公司设计一个员工反馈系统（原框架：收集-分析-汇报）。

- 选域：植物学（远距离）；
- 翻译：员工=植株、反馈=感知缺水的信号、汇报=向光调整；
- 观察：植物不"汇报"，它**即时调整朝向**——新框架冒出"反馈不再走汇报流程，
  而是触发即时调整"；
- 回流：把反馈从"收集-分析-汇报"重构为"感知-即时响应"。

**题目**：停车场总停不下（原框架：增加车位/优化引导）。

- 选域：蜂群（远距离）；
- 翻译：车=工蜂、车位=蜜源、绕行=信息素路径；
- 观察：蜂群无中心调度，个体通过环境痕迹协作——新框架冒出"让车位互相标记、
  车辆自行绕开满位区"；
- 回流：重构为"车位信息素"方案——车位被占时向周边车"释放信号"，无需中心系统。

## 四、注意事项

- **借框架 ≠ 借点子**：目的是改变"问题怎么定义"，不是直接抄答案；
- 一次只借一个领域，混着借会变成"跨域融合"（那是 creative-mind 的活）；
- 移植后必须过 frame_gap.py：翻译回去的问题如果和原问题结构相似度过高，
  说明没借到真框架，换一个更远的领域。
