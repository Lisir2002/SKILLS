# 六维度假设清单与常见认知框架

> frame-breaker Step 1 挖假设时使用。隐含假设是"框架"的组成单元——
> 把它们写成命题，框架就不再理所当然，才能逐条反演。

## 一、六维度假设清单

每个问题默认持有六类假设。审计时逐个过，别跳过"对象/目标"（它们通常最核心）。

### 1. 对象（Subject）

默认的"对象/主体/用户"是谁？假设了它是什么类型？

- 挖：谁是主角？用户是成人/企业/单人/活物？对象是实体还是流程？
- 反：换成别的物种/形态/尺度；对象消失会怎样？
- 常见脑补：用户=成年人、对象=当前物理产品、主体=单个而非系统。

### 2. 目标（Objective）

默认的目标是什么（更快/更多/更省/更好看）？**这个目标本身合理吗？**

- 挖：衡量"成功"的显式目标是哪个词？这个目标来自题面还是常识？
- 反：目标的反面是什么？"最不"要什么？
- 常见脑补："最小"=最小正数、"优化"=降本增效、"快"=物理速度（895 实验、
  slow-elevator 都是这类）。

### 3. 约束（Constraint）

默认的约束是什么？哪些约束**从未被题面声明**，是模型自己加的？

- 挖：列出现有方案不敢越过的线；区分"题面约束"与"脑补约束"。
- 反：把约束取反/删除/极端化。
- 常见脑补：必须保留现有形态、必须三个步骤、必须不改变 X、预算固定。

### 4. 过程（Process）

默认的解决过程是什么（运输/计算/传递/制造）？有没有另一种过程能达到同一目的？

- 挖：默认路径是哪条？它的前置/后置是什么？
- 反：如果过程完全不经过"它"，结果会怎样？
- 常见脑补：电梯=物理运输、产品=制造出来交付、提升体验=提升速度。

### 5. 评价（Evaluation）

默认用什么标准评价成功（时间/数量/成本/满意度）？**换评价标准会改变什么？**

- 挖：成功的长什么样？谁打分？按什么指标？
- 反：如果成功的新定义是旧方案眼里的失败，旧方案还成立吗？
- 常见脑补：用"到达用时"衡量电梯问题、用"销量"衡量营销、用"速度"衡量工具。

### 6. 边界（Boundary）

默认的解决范围边界在哪（这个系统/公司/学科/预算周期内）？

- 挖：默认在哪个边界内解题？边界外有什么被排除了？
- 反：边界扩大/缩小到极限会怎样？把外部性纳入会怎样？
- 常见脑补：在电梯系统内解决电梯问题、在公司内解决产品问题、在本题内解题。

## 二、模型最常见的认知框架（跨任务高频出现）

这些"默认框架"几乎会不自觉地套到任何问题上，审计时优先怀疑：

| 框架 | 默认表述 | 反演方向 |
|------|----------|----------|
| 最大化 | "做得更多/更大/更快" | 做得更少/更小/更慢 |
| 正向思考 | "如何实现 X" | "什么必定导致失败"（逆向排除） |
| 单一主体 | "用户是个人/产品是实体" | 对象是系统/生态/植物/程序 |
| 线性时间 | "现在 → 目标" | 从终点倒推/时间循环 |
| 物理解决 | "问题在物理层面" | 在感知/信息/社会层面解决 |
| 成本思维 | "在预算内做" | 把成本项反转成收益项 |
| 本系统内 | "在系统内部解决" | 把问题挪到系统外解决 |
| 独立方案 | "找一个方案" | 同时运行多个互斥方案/不做 |

## 三、怎么区分"题面给的"与"模型脑补的"

- **题面给的**：字面上明确声明（"移动两根火柴""预算 10 万"）——这些不能无脑反演；
- **模型脑补的**：题面没说，模型/常识自动补上的（"结果是正数""必须保留三位数"
  "用户是成年人"）——**这是主要破框目标**；
- 反演时优先对"脑补项"下手，它们往往就是 895 实验里那种隐形锁。

## 四、挖假设的正确姿势

- 一条假设 = 一个**可判定真假的命题**（不是形容词列表）；
- 写完六维后自问："哪条假设如果删掉，会让现有答案立刻崩塌？"——那条就是
  最值得反演的；
- 别急着合理：审计阶段只要"列全"，评价留到落地步骤。
