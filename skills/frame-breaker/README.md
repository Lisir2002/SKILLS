# frame-breaker · 认知突破（变革式创造引擎）

让模型**改变问题本身**，而不是在问题里找更好的答案。这是创造的最高阶——Boden 称之为"变革式创造"（transformational creativity）：修改问题表述、改变定义搜索空间的框架本身。模型天然缺这个能力（它默认在训练数据设定的框架内作答），本技能用五步引擎强制执行。

> 与 [creative-mind](creative-mind/README.md) 的关系：creative-mind 是"在框架内做得更好"（组合式+探索式），本技能是"改变框架本身"（变革式）。互补使用。

## 什么时候用

- 你说"突破认知 / 跳出框架 / 打破思维定式 / 重构问题 / 重新定义问题 / 变革 / 换个维度想 / 破框";
- 方案怎么优化都是换皮、走进死胡同时；
- 你说"这个问题本身可能就问错了 / 别在原框架里想"。

## 安装

```bash
# Trae / Claude Code 风格
mkdir -p <你的skills目录>/frame-breaker
# 把本目录内容（SKILL.md、scripts/、references/）复制进去即可
```

## 用法

在对话中直接触发，例如：

> 电梯太慢，怎么解决？（这个问题本身可能就定义错了）

> 别在原框架里想，帮我重新定义这个问题：`<问题>`

### 可选：挖假设（脚本）

把模型/用户对问题默认持有的隐含假设显式挖出来（六维度：对象/目标/约束/过程/评价/边界）：

```bash
python3 scripts/assumption_audit.py --problem "电梯太慢怎么办"
```

输出六维度假设挖掘脚手架 + 域外领域规则库清单，供反演与移植使用。

### 可选：框架差距检测（脚本）

验证重构是否真的发生（不是换皮）：

```bash
python3 scripts/frame_gap.py --original "如何让电梯更快" --reframed "如何让等待变得值得" --solution "电梯里做内容幕间，管理乘客对时间的感知"
```

输出"框架突破度"（0-100）：低于 60 说明还是换皮，回去再反演一轮。

## 工作方式（五步变革引擎）

1. **挖假设 Audit** — 六维度列出隐含假设，区分"题面给的"与"模型脑补的"；
2. **反演假设 Invert** — 逐条取反/极端化，建立 ≥3 个"反世界"（不追求合理）；
3. **域外移植 Transplant** — 从无关领域借"规则系统"重定义本题（不是借点子，是借表征框架）；
4. **重构问题 Reframe** — 产出新问题 + 框架前后对比，用 frame_gap 验证真变了；
5. **归零落地 Ground** — 落回现实：前 30 天动作 + 最大反对理由 + 最小验证。

## 示例

**用户**：电梯太慢，怎么办？

- 挖假设：对象=电梯、目标=更快到达、约束=不改硬件、边界=在电梯系统内……其中"慢=运输速度"是模型默认先验；
- 反演：反世界"电梯不负责运输" / "等待本身就是产品"；
- 移植：借"戏剧的悬念"——幕间等待不浪费，因为期待被管理；
- 重构：从"如何让电梯更快"→"如何让等待变得值得/被忽略"，突破度 84；
- 落地：30 天试点"楼层内容幕间"，最大反对=投入产出比，最小验证=3 层楼看投诉率。
