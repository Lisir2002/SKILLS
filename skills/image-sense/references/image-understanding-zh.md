# 无模型图像感知 · 原理与边界（image-sense）

本技能的目标：**在不使用任何模型的前提下**让"看图"能力落地——只有纯 Python 标准库，
没有视觉大模型、没有 PIL/OpenCV、没有 OCR 引擎、没有外部命令、没有网络。
这正是"接入一个没有识图能力的 API"时依然可用的路径。

## 一、可行性结论（2026-08 全网调研）

"不靠模型看懂图片"完全可行，但必须分清两层能力：

| 能力层 | 含义 | 无模型可否做到 | 用什么 |
|--------|------|----------------|--------|
| **感知层（perception）** | 读出"可从像素/字节算出的确定性事实"：格式、尺寸、颜色、明暗、结构、元数据、文字区域 | ✅ 完全可以 | 纯算法：解析、统计、启发式 |
| **语义层（semantics）** | 回答"这是什么场景 / 什么情绪 / 谁在做什么" | ❌ 纯算法做不到 | 需要模型（本技能明确不做） |

业界对"无深度学习看图"的公开结论：经典计算机视觉（OpenCV 的 Canny/Sobel 边缘、
LBP/GLCM/Gabor 纹理、直方图/主色、轮廓、模板匹配、分水岭、超像素）能稳定完成
"特征提取"类任务，且可解释、零训练；但**语义分类需要手工特征 + 分类器或神经网络**，
现实复杂场景泛化差（OpenCV 官方与多篇教程均如此表述）。因此本技能把"感知层"做足、
对"语义层"诚实拒绝——宁可给可验证的事实，不假装"看懂"。

参考来源方向：
- OpenCV 官方博客《Edge Detection Using OpenCV》（2025-05）——边缘/梯度/Canny 原理；
- 经典 CV 教程《OpenCV 计算机视觉实战·经典算法》——边缘、角点、轮廓、模板匹配、
  超像素等"无模型特征提取"方法谱系；
- 图像识别综述类文章（2025）——模板匹配、特征点匹配（SIFT/ORB）、分类器三分法；
- 多篇"如何识别照片"工程实践（2025-2026）——EXIF 元数据（相机/时间/GPS）、
  OCR、反向检索的组合侦察流程，证明"元数据 + 视觉特征"在不依赖大模型时也有价值。

## 二、本技能做到了什么（纯标准库实现）

| 能力 | 实现原理 | 覆盖格式 |
|------|----------|----------|
| 格式 / 尺寸 / 色深 / 色型 / 透明度 | 解析文件头与 chunk | PNG/JPEG/BMP/PPM/GIF/WebP |
| **像素级还原** | PNG：zlib 解压 + 逆滤波（None/Sub/Up/Average/Paeth），位深 1/2/4/8/16、色型 gray/rgb/palette/gray+alpha/rgba 全支持；BMP：BI_RGB 8/24/32；PPM：P3/P6 | PNG/BMP/PPM |
| **主色 / 明暗 / 饱和度 / 细节度** | 降采样后：RGB 量化桶统计、亮度均值、max-min 饱和度、相邻亮度差占比 | 有像素的格式 |
| **感知哈希 dHash** | 9×8 灰度相邻比较 → 64 位十六进制，用于相似图检索 | 有像素的格式 |
| **ASCII 预览** | 亮度映射成字符画，人眼直接看"这图长啥样" | 有像素的格式 |
| EXIF 元数据（相机/时间/GPS/软件） | 解析 TIFF IFD0 + GPS IFD（JPEG APP1 / PNG eXIf / WebP EXIF chunk） | PNG/JPEG/WebP |
| JPEG 头部信息 + 近似质量 | SOF 尺寸 + DQT 量化表均值估算 | JPEG |
| WebP 头部信息 | RIFF 容器 + VP8X 画布/标志 + VP8 有损尺寸（兼容 CDN 变体）+ VP8L 无损尺寸 + 动画帧 + EXIF | WebP |
| GIF 帧数 / 透明标志 | 图像描述符计数 + 图形控制扩展（不跑 LZW） | GIF |

> 可选解码器：WebP/JPEG 的像素级解码需完整位流解码器（VP8/Huffman+IDCT），纯标准库量级
> 过大；若环境装了 Pillow，脚本会用它**只做位图解码**（Pillow 是解码库，不是模型），
> 之后的特征/哈希/预览仍是无模型算法。没装 Pillow 就如实降级，不假装。

## 三、诚实边界（不许幻想）

1. **不做语义**：本脚本永远不说"这是一张猫的照片"。它只说"主色 #XXXXXX、
   占比 X%、细节度中、有透明通道"。语义问题回答"需要模型"。
2. **JPEG/WebP 不靠纯标准库做像素还原**：解码 JPEG 需完整 Huffman+IDCT、WebP 需完整
   VP8 位流解码器，量级是现有代码数十倍，超出"零依赖、可维护"目标。JPEG 只给头部+EXIF+
   近似质量；WebP 给头部+尺寸+EXIF。需要像素特征时，正确做法是装 Pillow（仍是解码库不是
   模型），脚本会自动用它解码后继续做无模型特征分析。
3. **不确定就报错**：任何一步解析失败都会降级（给头部信息 + pixel_error），
   绝不填充猜测值。`UNKNOWN` 格式返回退出码 3，方便上层识别"看不懂"。

## 四、如何用（给上层 API 的接线说明）

```bash
python3 scripts/image_sense.py photo.png --json        # 结构化事实
python3 scripts/image_sense.py photo.png               # 人读报告（含 ASCII 预览）
python3 scripts/image_sense.py photo.png --no-ascii     # 只要报告不要字符画
python3 scripts/image_sense.py --make-test-png t.png    # 生成自测图（冒烟用）
```

消费方拿到的 JSON 字段（`--json`）：
- `format / width / height / bit_depth / color_type_name / has_alpha / file_size_kb`
- `exif`：`拍摄时间 / 相机厂商 / 相机型号 / 软件 / ISO / GPS{lat,lon}`（缺省为空对象）
- `features`：`dominant_colors[] / brightness / saturation / detail / transparent_ratio`
- `dhash`：64 位感知哈希
- 若像素无法还原：`pixel_error` 说明原因；若格式未知：`error` + 退出码 3

## 五、为什么这样设计（与"接近/超越人类思维"的关系）

人类看图也不是一步到位：先是"感知"（颜色、形状、明暗、结构），再是"命名/语义"。
本技能把**可验证的感知层**做到确定、可解释、零成本——这一层是任何"看懂"的地基，
也是后续无论接什么模型都能用来交叉校验、防幻觉的锚点。语义层明确留给外部能力，
不与无模型路径混为一谈，避免"假装看懂"。
